# Coding Standards

- Prefer clarity over cleverness.
- Avoid global state; prefer local state and explicit dependency injection.
- Small files, small components with a single responsibility.
- Use pure functions whenever practical.
- Document public interfaces and repository contracts.
- Write tests for business logic and repository implementations.

Commit conventions:
- Small, focused commits
- Descriptive messages
- Keep the app runnable after each commit (per milestone guidance)
