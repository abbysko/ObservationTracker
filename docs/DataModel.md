# Data Model

## Current state

This project is currently a browser-first prototype. The live app persists data in browser storage using a lightweight schema that matches the current implementation, not the fully normalized future model.

### Lists

A list is a collection of items the user can browse and track.

Fields:

- id: string
- name: string
- builtIn: boolean
- items: array of Item objects

Example:

```json
{
  "id": "builtin-car-makes",
  "name": "Car Makes",
  "builtIn": true,
  "items": [
    { "id": "toyota", "name": "Toyota" },
    { "id": "ford", "name": "Ford" },
    { "id": "honda", "name": "Honda" }
  ]
}
```

Notes:

- Built-in lists are seeded from `web/data/builtins.json`.
- Custom lists are stored alongside built-ins in `localStorage` under the `ot_lists_v1` key.
- A custom list is created by duplicating a built-in list and marking the new item as `builtIn: false`.

### Item

Each item has a simple identity and label.

Fields:

- id: string
- name: string

Example:

```json
{ "id": "toyota", "name": "Toyota" }
```

### History sessions

Completed tracking sessions are stored as history entries in `localStorage` under the `ot_history_v1` key.

Fields:

- id: string
- listId: string
- listName: string
- autoGeneratedName: boolean
- endedAt: timestamp in milliseconds
- itemCount: number
- observedItemCount: number
- totalObservations: number
- items: array of observed items with count values

Example:

```json
{
  "id": "session-1720000000000",
  "listId": "builtin-car-makes",
  "listName": "Car Makes",
  "autoGeneratedName": true,
  "endedAt": 1720000000000,
  "itemCount": 42,
  "observedItemCount": 11,
  "totalObservations": 38,
  "items": [
    { "id": "toyota", "name": "Toyota", "count": 8 },
    { "id": "ford", "name": "Ford", "count": 5 },
    { "id": "honda", "name": "Honda", "count": 3 }
  ]
}
```

Notes:

- This is the actual persisted shape used by the current repository implementation.
- Session names are stored as `listName` rather than a separate `displayName` field.
- The repository adds `savedAt` when writing to history, but the core live session model still uses `endedAt` and `listName`.

### Active tracking state

The live tracking session is not stored as a single session object in the repository while the session is active. Instead, the app uses browser session storage to hold transient values such as:

- active list id
- active list name
- active session name
- per-item counts for the current list

This state is intentionally temporary and is cleared when a session is saved or discarded.

## Future target model

The future architecture is expected to evolve toward a more formal model, closer to the original product specification:

- List objects with stable identifiers and metadata
- Session records with a start time, end time, duration, and item-level counts
- Explicit history persistence independent of the active session state
- A repository boundary that can swap browser storage for native storage in an iOS wrapper

That future model is the correct design direction, but it is not yet the actual persisted schema of the current prototype.

## Summary

The current implementation is intentionally simple:

- List data is a plain object array.
- History data is a plain array of session objects.
- Active tracking state is stored in `sessionStorage` instead of a full in-memory session model.

This is sufficient for the current prototype and keeps the app easy to reason about while the repository abstraction remains lightweight.
